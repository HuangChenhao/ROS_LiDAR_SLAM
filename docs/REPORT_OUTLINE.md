# 项目研究报告与汇报提纲

## 1. 建议题目与主线

建议题目：**《基于 ROSMASTER R2 的多算法 SLAM 系统实现、故障诊断与实验评估》**。

核心研究问题：在 Raspberry Pi 5 与二维激光雷达条件下，如何为阿克曼机器人建立可复查的建图实验流程，并区分系统运行故障、地图显示问题与算法估计误差？

报告按“平台需求 → 系统实现 → 实验现象 → 原因诊断 → 修复验证 → 受控评估计划”展开。现有工作的贡献以系统集成、数据记录、故障诊断和验证方法为主；算法来自已有实现，应明确引用相应上游项目。正式报告加入相关工作时，再补查原始论文和官方资料。

## 3. 最值得讲清楚的四个案例

### 案例 A：有地图文件，后端仍可能已经崩溃

展示 SLAM Toolbox 的 `complete` 元数据、仅 3 点的轨迹，以及 probability-search 致命日志。说明实验成功应联合检查后端存活、有效地图更新与保存完整性，单一文件标签不充分。

7 月 23 日会话接收 561 帧扫描且没有同类致命异常，可作为阶段验证。当前 `baseline/` 已含部分早期修复，不能把这个目录直接等同于故障时配置。

### 案例 B：出现闭环关键词，不等于完成闭环

展示 RTAB-Map 的旧 `loop_events=1` 与实际提示文本，再展示数据库类型分布。把“日志文本检索”“约束存在”“成功闭环”“误差改善”分成需要逐步核验的四件事。

629 条优化器索引告警与后一次静止测试的 0 条告警可以描述现象差异；两次工况不同，不能据此量化修复对行驶精度或长期稳定性的因果作用。

### 案例 C：地图优化后，显示轨迹也要更新

展示旧 Cartographer 地图与在线轨迹的错位现象，再展示后续 `cartographer_pose_graph` 来源和优化轨迹文件。贡献是让导出和显示消费优化后的轨迹；后续还应在行驶闭环中验证。

### 案例 D：原始数据可读，也可能无法直接标准回放

展示 GMapping 的完整地图、空轨迹、含 NUL 的会话元数据和空 bag YAML。说明如何保存异常会话、直接核对数据库，并在副本上恢复标准回放所需信息。

## 6. 后续实验设计

### 第一优先级：利用已有 bag 做离线对照

选一份输入话题齐全的行驶 bag，固定数据、回放倍率、计算平台和地图分辨率。四种算法分别运行；如研究参数修改，每种配置在同一 bag 上配对运行，并保留配置和输出。现有回放工具只支持四类激光 SLAM，RGB-D 需扩展同步图像输入。

记录有效扫描处理数、后端退出情况、地图更新、CPU 时间、峰值内存和最终地图/图状态。当前回放工具已有部分指标，峰值内存、处理延迟和严格的闭环事件还需补充采集。

该实验能比较相同输入下的后端行为。使用固定 `/odom` 时，它无法检验不同里程计或传感器融合方案的收益。

### 第二优先级：同路线实车重复实验

建议起步规模为四种算法 × 两档速度 × 每条件至少三次，即 24 次会话。固定起终点位置与朝向、场景和预定路线，交错算法顺序，记录实际速度而非只记录档位。若工作量有限，先对全部算法完成统一低速条件，再扩展速度因素。

失败会话同样计入总次数，预先定义失败标准，例如后端退出、移动期间地图长时停更、传感器缺失或未完整落盘。记录每次故障原因，避免只比较成功输出。

### 第三优先级：加入参考测量与融合对照

- **参考轨迹存在时：**明确坐标对齐方法、时间同步和采样方式，再计算 ATE/RPE。
- **仅有测量地标时：**使用已测量的墙距、标志点或路线长度评估地图几何误差，报告测量不确定性。
- **重复回到同一物理位姿时：**计算首尾位置与朝向差，作为回归一致性指标；不替代全程精度。
- **RGB-D 融合：**先检查图像、深度、相机内参、TF 与时间同步，再与 LiDAR 方案做同场景对照。

资源占用、成功率和几何误差分开报告。每组给出单次结果与分布，避免只选择最好的一次。

## 7. 可直接使用的阶段摘要

本项目围绕 ROSMASTER R2 阿克曼移动机器人，开展了多算法 SLAM 系统集成、实验记录与故障诊断工作。系统以 Raspberry Pi 5 和 RPLIDAR A1 为基础，支持多种激光 SLAM 后端及会话化数据保存。现有本地材料包含 9 个 ROS2 会话，其中 8 个有非空 rosbag，累计约 33.7 分钟、14,882 帧激光扫描。通过交叉核对日志、轨迹和数据库，定位了后端异常、优化器告警、轨迹显示与记录完整性问题，后续静止验证确认了部分修复后的运行和导出功能。当前结论主要覆盖系统实现与功能验证，算法精度、速度影响和 RGB-D 融合收益将通过统一数据回放与受控重复实车实验进一步评估。
