## 2. 从版本之间看系统演进

### A. ROS1 首次可运行：v0.1.0-demo_test

**出发问题：**建图出现放射状结构，里程计输出无效；地图、轨迹和离线数据需要形成可查看的结果。

**当时的变更：**修订底盘命令与里程计回退逻辑，加入轨迹记录、定时地图切片、主机同步与离线后处理。历史源文件可从 [v0.1.0 标签树](https://github.com/HuangChenhao/ROS_LiDAR_SLAM/tree/v0.1.0-demo_test)检查。

**验证与局限：**旧 README 和 Release 记录了地图形态改善及匹配分数，但没有外部轨迹真值；使用 `/cmd_vel` 回退仍可能在打滑、转弯和轮子空转时与真实运动分离。该阶段属于可运行演示，不能称为完成闭环里程计标定。

### B. ROS1 收尾：v1.0.0-ros1-alpha

**出发问题：**设备映射、重复启动、地图保存、R2/X3 兼容逻辑、URDF/轴距和编码器/遥测状态交织在一起。

**当时的变更：**将问题、可能原因、诊断命令和迁移路径写入仓库，而不是只保留最终地图。

**验证与局限：**“固件限制”“编码器损坏”“ROS2 不再出现停更”等表述是历史判断或推测。现在按 [问题台账](ISSUES_AND_FIXES.md)核对其适用阶段和证据，不直接当成当前事实。

### C. ROS2 迁移：2026-07-04

**出发问题：**原 ROS1 流程依赖较多兼容补丁和脚本重启，后续算法、遥控和设备管理需要统一入口。

**变更依据：**[`3904b75`](https://github.com/HuangChenhao/ROS_LiDAR_SLAM/commit/3904b75)切换为 ROS2 Foxy 补丁结构和操作说明。该提交标题中的版本文字不是一个实际发布标签。

**结果：**运行入口逐渐集中到 `patches/` 和容器；ROS1 旧文件由历史标签保存。迁移本身不证明传感器、TF 或 SLAM 质量问题全部消失。

### D. 人机交互与生命周期：2026-07-15

**问题：**手柄晚出现导致控制链路不可用；动画覆盖红灯；重复 joy 实例；雷达、建图、屏幕和保存流程分散。

**变更：**`c05efa0` 增加 LED 和档位规则；`14f4a19` 引入监督器、DTR 雷达控制、全屏地图和会话保存。

**重要行为变化：**当日开发过程中曾从“低档建图”临时调整为“激活即建图”；之后版本恢复了高档/竞速结束建图。旧工作日志不是当前操作规则，复现实验必须关联具体提交。

### E. 双算法与显示诊断：2026-07-17

**问题：**户外地图碎裂、低压后 TF 断裂、Cartographer 输出中墙体显示缺失，以及缺乏离线重建入口。

**变更：**`e7ebf86` 接入 Cartographer；渲染从 `==100` 改为概率阈值；增加 bag 时钟与重建管线。

**验证边界：**研发日志记录过同场地约 4–5 分钟的观察和一次离线重建成功。本次发布没有那批对应的原始 bag；不能把日志中的“户外首选”扩大为普遍排名，也不能把修复渲染直接当成提升估计精度。

### F. 里程计、EKF 与四后端扩展：2026-07-20

**问题：**原始位姿出现不合理跳变，绝对位姿进入 EKF 后可能污染输出；启动与手柄重连需要更完整的检查。

**变更：**`1cfbb84` 加入速度主导的 EKF 输入配置、启动错误处理和重连逻辑；`bfec5c5` 加入另两种后端配置及相关状态展示。

**后续演进：**7 月 23 日又加入专用里程计和健康检查。参数在多个阶段有修改，因此当前 YAML 不应被回填成所有历史会话的精确配置。

### G. 四算法与防护收束：v2.0.0-ros2-mapping

**问题：**后端崩溃、优化器告警、地图显示轨迹未重写、GMapping 大图越屏、传感器/串口异常和会话标签竞态。

**变更：**`31c2bb2` 修改 15 个文件；新增稳定里程计、健康检查和 launch，扩展监督器、录制话题、档位事件、图轨迹和故障停止逻辑。

**对应证据：**7 月 22 日 6 次会话与 7 月 23 日 3 次静止验证，详见[实验盘点](EXPERIMENTS.md)。其中包含失败和不完整会话，不能仅凭 Release 的功能介绍认定所有动态问题已修复。

### H. 展示、审计与数据发布：2026-11-18 / v2.1.0-research

**问题：**线上首页主要是操作指南；原始 bag 未提供公共下载；几次版本的改动和问题缺少统一关联。

**变更：**展示首页、实验总表、原始归档与校验、版本演进、问题台账、下载恢复和后续记录模板。`research/` 的结束流程、回放和 RGB-D 配置与运行补丁分开保存。

**重要范围：**`patches/` 与 `systemd/` 相比 v2.0.0 无运行内容差异；本版是数据与研究记录的里程碑，不代表已部署新算法或完成新的实车精度实验。

## 3. 数据、代码和验证怎样关联

| 证据 | 可以确认 | 不能单独确认 |
|---|---|---|
| 标签与提交 | 源文件在某个历史点的内容 | 机器人当时实际部署的全部配置 |
| 代码 diff | 实现与参数变化 | 变化已实测有效或有因果精度收益 |
| 会话日志和 SQLite | 收到的话题、故障文本、采集时段 | 真实位姿与完整运行质量 |
| 地图与轨迹 | 系统输出和内部一致性现象 | 没有基准时的全程定位精度 |
| 静止验证 | 一段静止运行、保存和停止行为 | 高速、打滑或动态闭环性能 |
| 外部参考测量 | 在约定对齐与同步方式下的误差 | 与不同工况、不同数据的直接横向排名 |

## 4. 后续发布规则

- 小范围文档或说明修正直接提交；不要求每次提交创建 Release。
- 当代码、实验数据或研究结论达到一个值得固定和引用的节点时，创建标签与 Release。
- 尚缺动态对照、完整部署验证或传感器标定时，明确使用预发布状态，并列出限制。
- 每个版本列出新增、修复、行为变化、验证方法、相关会话、已知问题和升级影响；使用[变更记录模板](templates/VERSION_CHANGE.md)。
- 新版本不覆盖旧数据附件、不移动已发布标签。新采集按新会话 ID 保存，数据修正另建版本并说明原因。
